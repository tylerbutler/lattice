## Design Specificity Verdict

**Authored and product-specific, with credibility leaks at the moments that matter most.** The Bricolage/Atkinson typography, flat plum notebook surfaces, state-shape taxonomy, and merge-focused content make the site recognizably lattice rather than default Starlight. The visual system supports the product's precise, mathematical, approachable positioning.

The main loss of specificity is semantic rather than stylistic. The repeated page-title block ornament is decorative instead of explanatory, and the dark palette makes nearly every surface and text tier pink or plum, so the designated proof/action color no longer carries distinct meaning.

**Deterministic scan:** The CLI detector returned zero findings for `website/`. Browser injection produced 16 signals across four routes. Most were false positives caused by visually hidden text, collapsed mobile TOC content, Expressive Code internals, the Mermaid diagram, and normal long-form column height. The browser pass did confirm two real visual defects: the package table expands the mobile document to 519px on a 390px viewport, and a Quick Start section rule intersects a wrapped heading.

**Visual overlays:** Injection succeeded in automated Chrome tabs, but no persistent user-visible browser tab is available.

## Overall Impression

The website already has a memorable, disciplined identity and unusually honest technical content. Its biggest opportunity is to turn mathematical correctness into an unmistakable journey: one exact proof, one recommended route, one clear first success. Right now the homepage proof is ambiguous, package choice becomes hostile on mobile, and Quick Start continues well past the beginner's first win.

## What's Working

1. **Strong identity:** The plum notebook surfaces and Bricolage/Atkinson pairing make the docs feel authored for lattice.
2. **Excellent orientation chrome:** Active sidebar states, reading paths, search, mobile navigation, skip links, focus treatment, and reduced-motion support are thoughtful.
3. **Trust-building substance:** Real package boundaries, executable examples, a dependency diagram, and an honest pre-1.0 warning replace generic marketing claims with evidence.

## Priority Issues

### P1 — The flagship proof is mathematically ambiguous

**Why it matters:** The homepage shows both replicas as `max(a:2, b:3)` and then reports 5. It visually reads as `max(2,3)=5`, undermining the site's central promise to make correctness visible.

**Fix:** Show each replica's vector separately, then the merged vector and derived read:

- A local: `{a:2, b:0}`
- B local: `{a:0, b:3}`
- Merged: `{a:2, b:3}`
- Value: `sum(values)=5`

Link the artifact directly to the tested merge laws.

**Suggested command:** `/impeccable clarify website/src/content/docs/index.mdx`

### P1 — Package selection breaks on mobile and for assistive technology

**Why it matters:** At 390px, the package table is 503px wide and expands the document to 519px, pushing header controls off-screen. Version and Docs badge links expose empty accessible names.

**Fix:** Replace badge-only anchors with explicit text links such as “v1.1.0 on Hex” and “API docs.” At narrow widths, transform each package row into a labeled card instead of compressing four table columns.

**Suggested command:** `/impeccable adapt website/src/content/docs/packages.md`

### P2 — Quick Start confuses first success with an API showcase

**Why it matters:** A beginner reaches convergence after the first GCounter example, then must process timestamps, deterministic tie-breaking, `CrdtSpec`, union matching, and ORMap callbacks. The first success is buried inside a roughly 3,800px mobile page.

**Fix:** End the core Quick Start after GCounter with a run command, expected output, and explicit “you have a convergent counter” checkpoint. Move LWWRegister and ORMap into next recipes or advanced disclosures.

**Suggested command:** `/impeccable distill website/src/content/docs/quick-start.md`

### P2 — Magenta no longer communicates meaning

**Why it matters:** Prose, navigation, borders, code, links, selected states, and cards all share a pink/plum voice. This violates the design system's One Proof Color rule and makes hierarchy flatter than the layout intends.

**Fix:** Use quieter neutral ink/blush values for prose and structure. Reserve convergence magenta for links, focus, current state, and primary actions.

**Suggested command:** `/impeccable quieter website/src/styles/custom.css`

### P2 — The index repeats choices and ends in anxiety

**Why it matters:** Two hero actions, four decision-path cards, and four state-shape rows repeat orientation decisions. The final substantive element is the pre-1.0 warning, leaving caution as the emotional endpoint.

**Fix:** Declare one recommended newcomer route, organize alternatives by reader intent, and follow the warning with a trust-recovery action such as “Prototype safely,” linking to Quick Start, version pinning, and stability details.

**Suggested command:** `/impeccable onboard website/src/content/docs/index.mdx`
