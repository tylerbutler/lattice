# Website critique

**Design health: 28/40 (Good).** Keep the worked counter. Fix the path from “I understand why these replicas converge” to “I know what to install.” The site explains the first part better than the second.

**Scope:** the local production build of `website/`, including Home, Quick Start, Packages, Installation, and representative guides. The design review followed links on desktop (1440 × 900) and mobile (375 × 812), including mobile search and navigation. These are expert walkthroughs, not observed user sessions.

## What works

- **The site does not read like an AI-generated devtool page.** The home page earns its large `5`: readers can see why two local counters merge to that value. Quick Start uses the same inputs and names the file, the run command, and the expected output. That recognition is the high point of the journey.
- **The brand serves the reading task.** Bricolage Grotesque distinguishes headings from Atkinson Hyperlegible body text. The plum surfaces and magenta active states let a reader find the current page without taking attention away from the code.
- **Advanced material stays optional.** A newcomer can finish the counter without opening the register or map recipes. An experienced reader can follow a recipe fragment and land in the expanded example.

## Fix in this order

1. **P1 — Make the umbrella install example safe to copy.** [Installation](../../website/src/content/docs/installation.md#L6-L27) promises “every CRDT in one dependency.” The [Packages import block](../../website/src/content/docs/packages.mdx#L52-L68) then shows `lattice_presence`, `lattice_fugue`, and `lattice_text_fugue`, none supplied by the [umbrella](../../packages/lattice_crdt/gleam.toml#L8-L15). Use “core toolkit” at the command. Keep only included imports in that example; give separate headings to the optional presence package and the two unpublished, local-path packages. `/impeccable clarify website/src/content/docs/packages.mdx`
2. **P1 — Make the release note trustworthy at the point of installation.** The [homepage caution](../../website/src/content/docs/index.mdx#L110-L115) identifies 3.x as current; [Hex lists 4.0.0](https://hex.pm/packages/lattice_crdt/4.0.0). The [Installation link](../../website/src/content/docs/index.mdx#L125-L133) promises to show how to pin a validated version, but its destination gives only unversioned `gleam add` examples. Link to the current release rather than hard-coding the major in prose. Show one exact-version dependency example beside the install command. `/impeccable harden website/src/content/docs/installation.md`
3. **P1 — Send readers who choose presence to the Presence guide.** The [“Sets + presence” row](../../website/src/content/docs/index.mdx#L97-L101) takes everyone to Sets. That article has no link to Presence in its body; search or the sidebar is needed to recover. Keep “Membership” as a group, but give readers two direct links: “Set membership” and “Who is online?” `/impeccable clarify website/src/content/docs/index.mdx`
4. **P2 — Put the package decision before the inventory.** At 375 px wide, the 12 catalog cards occupied about 4,685 vertical pixels. [“Which approach to choose”](../../website/src/content/docs/packages.mdx#L70-L84) began about 6,767 px down, after the catalog, graph, and imports. The section jump works, but first-time readers should not need it. Start with the existing rule: umbrella for a prototype, one focused package for one data type, presence separately. Keep the table and graph below for lookup. `/impeccable layout website/src/content/docs/packages.mdx`

## Cognitive load and reader impact

The first counter has one recommended action. Package selection fails three of the eight cognitive-load checks: grouping choices into small sets, limiting choices at a decision, and avoiding recall across pages. The docs menu has 13 destinations in groups of 4, 6, and 3. That is reasonable for reference navigation. The problem is making a new reader interpret 12 package entries before explaining the choice.

| Reader | Where the path breaks |
|---|---|
| Jordan, trying CRDTs for the first time | Can copy imports from Packages that the recommended install does not provide. |
| Casey, looking up live membership on a phone | Can select the right word, “Membership,” and still need search to get to the Presence guide. |
| Riley, checking release claims before adoption | Finds a different major on Hex than in the site's release caution, then cannot find the promised pinning example. This is the low point of the journey. |

## Smaller design opportunities

The worked example started about 1,097 px down at 1440 × 900. Try putting a compact version of the two states and their merged result beside Quick Start, without adding a second primary action. For the reading path, use “sections” for the top-level count or drop the count when subsections make “stops” ambiguous.

## What the detector added

The source scan of `website/src` returned no findings. The four-page compiled scan returned five, all false positives: `single-font` on Home, Quick Start, and Packages; `flat-type-hierarchy` on Quick Start; and `em-dash-overuse` on Packages. Computed styles showed both font families and distinct heading and body sizes. The visible package table contained one prose dash, not 26.

The light-theme browser scan reported two findings on Home, one on Quick Start, and none on Packages or Installation. Both Home findings held up: the release caution had a line of about 93 characters, and [route links](../../website/src/content/docs/index.mdx#L354-L369) shift their text by about 10 px on hover. Limit the caution to 65–75 characters per line and use a background or underline for hover instead of moving the text. Reduced-motion mode already disables that shift. The Quick Start warning concerned a visually hidden heading-link label, not a paragraph readers see.

In the separate dark-theme **[Human]** tab, 20 overlays on the Packages import block marked syntax tokens as an “AI color palette.” These marks are visible on the loaded page and are not a reason to recolor the site. The checks sampled specific routes and text/background pairs; they are not a site-wide accessibility certification.

## Design decision for the next pass

Put the first successful install ahead of the complete reference inventory. The counter already shows how this can work: give the reader a small result they can verify, then offer the details.
