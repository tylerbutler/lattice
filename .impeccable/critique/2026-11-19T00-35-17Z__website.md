# Website critique

**Score: 28 out of 40.** The site earned a Good rating. A new reader could follow the counter example and know why the answer was `5`. The same reader could follow the recommended install and copy imports for three packages it did not include.

This review covers the [site before the fixes][reviewed-site]. Two agents inspected a local production build of the homepage, Quick Start, Packages, Installation, and selected guides. The review included desktop at 1440 by 900 pixels and mobile at 375 by 812 pixels, including mobile search and navigation. No users took part.

## What to keep

The worked merge distinguished this homepage from a generic developer site. The homepage showed a count of 2 at one node and 3 at the other. Quick Start used the same counts, named the file to save, and gave the command to run. Readers could check the result against the `5` they had seen on the homepage.

Bricolage Grotesque headings were easy to distinguish from Atkinson Hyperlegible body text. Magenta marked the current page against a plum background. Readers could finish the counter tutorial without opening the register or map recipes. A direct link opened the relevant recipe.

## Fix in this order

1. **P1. Separate the imports by install method.** [Installation][install] promised "every CRDT in one dependency." The [import example][imports] included `lattice_presence`, `lattice_fugue`, and `lattice_text_fugue`. None appeared in the [umbrella dependencies][umbrella]. Show the core imports beside the install command. Give presence its own example and the unpublished Fugue packages their own local install instructions. `/impeccable clarify website/src/content/docs/packages.mdx`
2. **P1. Show how to pin a tested release.** The [homepage release note][release-note] named the 3.x umbrella, but [Hex listed 4.0.0](https://hex.pm/packages/lattice_crdt/4.0.0). The [link to Installation][pin-link] promised pinning instructions. Readers found only unversioned `gleam add` commands there. Link to Hex for the current release. Give one exact version as an example beside the install command. `/impeccable harden website/src/content/docs/installation.md`
3. **P1. Give presence its own link.** The ["Sets + presence" link][membership] led to Sets. That article had no link to Presence in its text. Readers had to use search or the sidebar. Keep both choices under "Membership" and label them "Set membership" and "Who is online?" `/impeccable clarify website/src/content/docs/index.mdx`
4. **P2. Give the package recommendation before the catalog.** At 375 pixels wide, the 12 package cards took up about 4,685 vertical pixels. ["Which approach to choose"][package-choice] began about 6,767 pixels down, after the dependency graph and imports. The section link worked, but new readers had to know which section to skip to. Start with the umbrella for prototypes. Explain when to install an individual package and when to add presence. Keep the catalog and graph for reference. `/impeccable layout website/src/content/docs/packages.mdx`

## Reader tasks

The homepage had one recommended action for the first counter. The docs menu divided 13 links into groups of 4, 6, and 3. The 12 catalog entries were useful for lookup, but readers saw them before the recommendation. Package selection failed three of eight checks: group related choices, limit the number of choices at one step, and avoid making readers recall exceptions from another page.

The reviewers used three example readers. Jordan, new to CRDTs, could copy imports the recommended install did not provide. Casey could choose "Membership" on a phone and still need search to find Presence. Riley, checking versions before an install, would find a different major release on Hex and no example of how to pin it.

## Homepage layout and reading path

At 1440 by 900 pixels, the worked counter started about 1,097 pixels down the homepage. Put the two local states and the merged result beside the Quick Start link. Keep Quick Start as the only primary action. In the reading path, label the count as top-level sections or remove it.

## Detector results

The source scan of `website/src` reported no findings. A scan of four built pages reported five false positives. `single-font` flagged Home, Quick Start, and Packages. `flat-type-hierarchy` flagged Quick Start. Reviewers checked the computed styles and found two font families and distinct heading and body sizes. `em-dash-overuse` reported 26 dashes on Packages. Only one appeared in the visible table text.

In the light theme, reviewers confirmed both findings on the homepage. One line in the release note was about 93 characters long. [Navigation link text][hover] moved about 10 pixels on hover unless the reader had enabled reduced motion. Limit the release note to 65 to 75 characters per line. Use a background color or underline to mark a hovered link without moving its text.

The one browser warning on Quick Start concerned a visually hidden heading link label. The browser scan reported no findings on Packages or Installation in the light theme. In the dark theme, the detector marked 20 syntax tokens in the Packages import example as an "AI color palette." Those were code colors and needed no change. The review covered selected pages and text colors. It was not a full accessibility audit.
