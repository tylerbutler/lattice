## v1.0.0 - 2026-07-07


### MajorRelease

#### Stable 1.0 release with a committed public API

`lattice_text` is now 1.0. Its plain-text CRDT API — grapheme-based insert, delete, and range operations, merge and delta-state mutators, cursor anchors, compaction, and JSON serialization — is stable and safe to depend on. From this release on, the package follows semantic versioning, so any future breaking change will come with a new major version.


### Added

#### Add a plain-text CRDT package

Introduces `lattice_text/text` with index-based insert/delete operations, YATA-style left/right origins, tombstone deletes, merge support, delta-state mutators, and JSON serialization.

#### Add richer grapheme-based text operations

New query helpers `length`, `substring`, and `try_substring`, plus plain, `*_with_delta`, and `try_*_with_delta` variants for `delete_range`, `replace_range`, and `move`, and total `append`/`append_with_delta` helpers. Range operations validate `0 <= start <= end <= length` and return the `RangeError` type on invalid input.

#### Add grapheme-level cursor anchors with `anchor_at`, `resolve_anchor`, and JSON serialization

Anchors are stable positions that survive concurrent edits and merges, so editors can keep cursors and selections in place across remote inserts and deletes. `anchor_at`/`try_anchor_at` create an anchor at a grapheme index with a `Before` or `After` bias, `resolve_anchor`/`try_resolve_anchor` map it back to a current index, and `start_anchor`/`end_anchor`/`anchor_to_json`/`anchor_from_json` round out the surface without callers needing to import `lattice_sequence`.

#### Add `compact`, `remove_forwardings`, and `frontier` passthroughs

Text documents compact through the underlying sequence without importing `lattice_sequence`: stable tombstones are dropped and stable grapheme runs merge into compact blocks. Anchor resolution resolves through forwardings for compacted graphemes; `try_resolve_anchor` returns `UnknownAnchorTarget` for anchors whose forwarding entry the host has expired — treat it as "re-anchor".


### Changed

#### Refactor grapheme/range logic onto lattice_text_core

Internal-only change: the multi-grapheme insert/delete fold loops and the substring slice helper now delegate to the shared `lattice_text_core` package. Public API and behavior are unchanged.


### Performance

#### Batch multi-grapheme inserts into a single sequence operation

Inserting or pasting a string now issues one batched backend insert covering every grapheme instead of one insert (and one delta merge) per grapheme, removing a large multiplier from building or pasting text.
