# Product

## Register

brand

## Users

Gleam developers evaluating CRDTs for distributed applications. They are usually deciding whether lattice is mathematically sound, easy to adopt, and practical across Erlang and JavaScript targets. They need fast orientation, credible examples, clear package boundaries, and enough confidence in merge semantics to install the right package.

## Product Purpose

lattice is a modular CRDT library for Gleam. The project exists to make conflict-free replicated data types approachable without hiding their correctness model: developers should understand what each type does, choose the smallest package they need, and trust that merge behavior is tested and portable. Success means a developer can move from evaluation to a working convergent data structure quickly, with confidence in API stability notes and serialization behavior.

## Brand Personality

Precise, mathematical, approachable. The voice should feel rigorous without becoming academic, technical without relying on developer-tool clichés, and friendly enough that CRDT newcomers are invited in rather than screened out.

## Anti-references

Avoid generic SaaS/devtool landing-page clichés: gradient heroes, hero metric blocks, repeated identical icon-card grids, vague "scale your workflow" copy, and decorative technical gloss. The site should not look like a toy demo, but it also should not become a dense research-paper archive.

## Design Principles

1. Make correctness visible: use examples, guarantees, and property-tested claims as the persuasive core.
2. Prefer exact orientation over spectacle: help visitors choose packages and CRDT types before adding visual flourish.
3. Teach through small working artifacts: code, diagrams, and concise comparisons should carry more weight than slogans.
4. Preserve mathematical calm: visual choices should feel ordered and intentional without becoming sterile.
5. Respect the pre-1.0 contract: communicate capability and caution clearly so trust comes from honesty.

## Accessibility & Inclusion

Target WCAG 2.2 AA. Future design work should maintain high contrast for documentation and code, preserve clear focus states, support reduced motion, avoid color-only distinctions in diagrams or status cues, and keep CRDT explanations readable for both experienced distributed-systems engineers and developers encountering the concepts for the first time.
